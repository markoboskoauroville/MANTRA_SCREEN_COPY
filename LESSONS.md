# LESSONS: Screen Copy (Mantra)

- 13.11.2026 scrcpy 4.x changed its wire format: video has session packets (bit 7) with the size, no width/height after the codec id; every media packet has a 12-byte header. The documentation (doc/develop.md) does not list the control message layouts: they are in app/tests/test_control_msg_serialize.c.
- The forward-tunnel dummy byte arrives right after the first accept; the device name and codec id only after all three sockets are connected. Reading them before connecting audio and control deadlocks.
- GitHub's private-repository minutes were blocked ("recent account payments have failed"): the repository is public by rule (building-repos-public.md), after the three secret checks.
- Mac microphone to the phone's WhatsApp call: see the section in the session report; Android does not mix another app's playback into a call's uplink, and the Mac cannot be a USB audio gadget. Real options: hardware (USB-C audio adapter with a cable from the Mac's output), WhatsApp Desktop on the Mac, or an emulator with the host microphone.
- 14.11.2026 "No route to host" from `adb connect` to a LAN phone that answers `nc` = macOS Local Network privacy on the adb SERVER process, which carries the permission of whichever app started it first. Proof: a second server from the terminal (`ANDROID_ADB_SERVER_PORT=5038 adb connect …`) connects at once. Fix without killing the shared server: a relay on 127.0.0.1 inside an app that has the permission.
- 14.11.2026 Rotation that "comes back": the second press of an impatient user undid the first (the toggle used the last wish and the readback was taken too early). Hold presses until the picture turned. `cmd window fixed-to-user-rotation -d 0 enabled` makes the display keep the user rotation even when the app in front asks for portrait.
- 14.11.2026 v22: the phone reaches the Mac through `adb reverse`, which is per adb device serial; the reverse must be applied again after every reconnect (it dies with the adb connection) and removed on quit. A client that closes is noticed by a blocking recv returning 0; a failed send shuts the socket down so the same path cleans up. The microphone prompt is keyed to the app's signature: after install re-sign with "Mantra Apps" so the permission survives updates.
- 14.11.2026 v23: v22's AVAudioConverter path (Float32 48 kHz mono to Int16 16 kHz) delivered full-scale noise; v23 resamples by hand (streaming box filter) and clamps*32767 to Int16 itself: clean. Debug aid: the first 4 s of what is sent go to ~/Library/Logs/ScreenCopyMicLink.wav, the log shows the mic input level every 5 s. Check by nc capture, sox stats and POST to :8837/hear next to `sox -d` at the same time.
- 14.11.2026 v25: all three scrcpy sockets (video, audio, control) share one adb transport. On a slow route the audio waits behind video bursts, so a jitter buffer alone cannot fix it: lower the video (2 Mbit/s, 30 fps) and send the sound as Opus (128 kbit/s instead of 1.5 Mbit/s raw). `tailscale ping` saying "via DERP(fra)" means a relayed path (phone on mobile data): expect 80-120 ms and plan every timeout around at least two round trips.
- 14.11.2026: a client that connects and closes after 0 bytes is a client-side timeout, not the server: measure the handshake from the phone (`(echo "TTT-MIC 1 16000"; sleep 2) | toybox nc 127.0.0.1 8879` timed with date +%s%N).
- 14.11.2026 v27: a shared resource on the Mac (the microphone) offered to every connected phone at once is a trap: Marko dictated on the Pixel glass and got the Mac mic. `adb reverse` from many phones to ONE Mac port hides who is asking; give each phone its own Mac port behind the same phone port, and decide per phone (driven from the Mac right now or not). Predict the other phones in the room before shipping a link.
- 14.11.2026 v29: mute on the Mac side only (a static gain flag read in the render callback), never the phone's volume: it covers phones connected later, costs no reconnect and leaves the mic link alone. A level meter must be fed even for tabs whose player is not enabled, so measure in feed() before the enabled check, and treat "no packet for 0.25 s" as silence, otherwise the bar freezes at the last level.
- 14.11.2026 v30: a peak hold needs a timestamp per channel, not a falling rate; a Python slice replace with a failed index (`index` found an earlier match) became replace("", ...) and inserted 148,000 lines: always search from the anchor start and check `git diff --stat` before committing.

## v32 (21.11.2026): the pipe leak
- Symptom: PIPE fds grew ~18/min idle (2,540 after an hour), then record start, status-file writes (Cocoa 512) and captures failed. lsof showed single unpaired pipe ends: the parent's write end of every Pipe() given to a Process was never closed (Foundation leaves it open until the Pipe deallocates, which did not happen reliably).
- Root cause: app/Adb.swift runCmd() (every adb call, discovery every 6 s, tailscale status) and Updater.run, plus the long-lived scrcpy `adb shell` pipe in Session.swift. Fix: runCmd closes the write end right after run(), closes the read end after waitUntilExit, SIGTERM then SIGKILL on timeout; Updater.run uses runCmd; the scrcpy shell pipe is kept in shellPipe and closed on termination/teardown. The app logs "open file descriptors: N" every 60 s.
- Rule: every Process with a Pipe goes through runCmd; never a second hand-rolled Process. Written by MAI Code 2 in one run (164 s), reviewed by Claude, green on the first CI run.
