# TAKEOVER: Screen Copy (Mantra)

A Swift Mac app (bundle id community.auroville.screencopy, installed as /Applications/Screen Copy (Mantra).app, signed "Mantra Apps"): a tabbed screen copy of Marko's Android phones, one tab per phone, every stream running in the background. It finds the phones by itself and puts them on cards, one card per physical phone, with all its routes (USB, Wi-Fi, Tailscale).

## Architecture chosen: (a) our own client of the scrcpy server protocol
scrcpy's desktop client is an SDL window and cannot be embedded in a tab, so the app speaks the scrcpy-server protocol itself (scrcpy 4.1, Apache-2.0, jar bundled in server/ and copied into the app's Resources):
- push the jar to /data/local/tmp, `adb forward tcp:0 localabstract:scrcpy_<scid>`, start `app_process ... com.genymobile.scrcpy.Server 4.1 key=value ...` with tunnel_forward=true;
- three sockets in order video, audio, control on the forwarded port; the dummy byte, the 64-byte device name, the codec id; 4.x media packets with a 12-byte header (config flag bit 6, key bit 5, pts, size) and 12-byte session packets (bit 7 set, width, height);
- video H.264: Annex-B split, SPS/PPS to a CMVideoFormatDescription, AVCC samples into an AVSampleBufferDisplayLayer (VideoToolbox hardware decode) with DisplayImmediately; tab switch sends RESET_VIDEO so a fresh key frame arrives;
- audio: audio_codec=raw (16-bit 48 kHz stereo, nothing to decode) played by one shared AVAudioEngine, one player node per tab (own volume and mute), only the active tab by default, or ALL TABS; the Mac's default output is used and the app never changes the Mac's audio device (the ADAM D3V is the boss);
- control: touch (pointer id -1), scroll, keycodes, text, paste (SET_CLIPBOARD), BACK/HOME/APPS. Layouts (big-endian) from scrcpy's test_control_msg_serialize.c.

## Sound rule: pre-fader
audio_source=playback (AudioPlaybackCapture), no audio_dup, so the phone stays silent in the room and the Mac hears the sound before the phone's own volume. Per tab switch PHONE SILENT / PHONE SPEAKS (audio_dup, restarts the stream). Bottom strip PHONE VOLUME sets the phone's own media/ring/alarm/call volume (`cmd media_session volume --stream N --set`, read back), for this phone or all phones; it never changes what the Mac hears.

## Discovery (Discovery.swift, every ~6 s, scan every ~24 s)
`adb devices -l`; `adb mdns services` (_adb-tls-connect); a port-5555 scan of every private /24 the Mac is on; Tailscale peers (Tailscale status --json, Android, port 5555); each found address gets `adb connect`. Routes are merged by `ro.serialno` into one Phone. Route order: USB, Wi-Fi, Tailscale, then measured round trip. A tab follows the best route and falls over by itself when it drops; a click on a route badge forces that route (click again to release). A USB-only phone gets ENABLE WI-FI AND TAILSCALE ACCESS (`adb tcpip 5555`). PAIR A PHONE runs `adb pair`.

## Build and install
Never compiled on the Mac: push to main, .github/workflows/build.yml (macos-15) builds, release v<N> marked Latest. Install: gh release download, codesign --force -s "Mantra Apps" (bundle id above), copy to /Applications. The repo is public (modules/building-repos-public.md: private minutes are blocked by billing), no README, no description. Version is `let VERSION = N` in app/App.swift, whole numbers.

## URL scheme / log
`open -g screencopy://tab/2` selects tab 2; log in ~/Library/Logs/ScreenCopyMantra.log (window number, per-tab fps and audio level every 5 s). Launch argument --muted starts every tab muted (tests).

## Not done in v1
Mac microphone to the phone (see LESSONS.md: no way without root or hardware), phone microphone to the Mac, camera, recording, file drop.

## State at v8 (13.11.2026): the simple version Marko asked for
Window = tab row (one tab per phone, greyed while a phone is away) + the phone picture + ONE line: [volume slider "8 / 16"] [PORTRAIT | LANDSCAPE]. Nothing else on screen. Every phone discovery finds gets its tab and stream by itself (no Connect); the cards panel exists in code (Panel.swift) but is never shown; Scan now, Add an address, Pair a phone and the adb tcpip switch live in the "Phones" menu of the menu bar. Sound: every phone, playback capture (pre-fader), no audio_dup, to the Mac's default output; no Mac-side controls. The slider is the phone's own media volume (`cmd media_session volume --stream 3 --set`, then waits for it to apply and reads back; volume keys as a fallback), polled about once a second so it follows the phone's own buttons. PORTRAIT | LANDSCAPE sets accelerometer_rotation 0 and user_rotation 0/1 and lights the one matching the real picture size (a portrait-locked home screen stays portrait). Immersive: double-click the picture or Cmd+F (also the green button); only the picture; Tab / Shift+Tab next/previous phone, Esc or F leaves; cursor hidden after 2 s. Test hooks: `open -g screencopy://tab/N`, `screencopy://volume/N`.
Lessons: the phone applies a volume change after a second or more, so read back late; Nothing's launcher ignores rotation; GitHub macOS runners sometimes fail with "job not acquired" (capacity), a re-run is enough.

## Where it stopped (13.11.2026, v15 installed and running)
v15 = v14 + the fix that ROTATION_90 from `dumpsys window displays` is rotation 1 (before, a phone that really turned also had its picture turned, so it looked wrong). v14 made reconnect robust: discovery never remembers a failed identity read (that was the cause of the Pixel tab sitting on SEARCHING after it came back: its address had been cached with an error text as its id), a returning phone gets its old scrcpy server killed and its forward removed, the addresses that worked before are tried when discovery has nothing, and `cmd window user-rotation -d 0 lock 0|1` (the `-d 0` is required on these phones) is read back with a 3 s wait; if the front app keeps the phone upright the picture is turned by capture_orientation=270 instead. Seen: a killed stream comes back in 3 to 9 s on both phones; Nothing and Pixel rotate and return to portrait. Not seen: a phone that really disappears for minutes and returns (only simulated by killing its server); a long landscape session on the Pixel; the immersive view and Tab key by a real keyboard; sound by ear with audio_dup on. Both phones were left portrait at their own volumes (Nothing 0/16, Pixel 17/25 as Marko had it).

## Where it stopped (14.11.2026, v21 installed and running)
- **The Pixel on Wi-Fi was not found** because the shared adb server (started at login by another app, orphaned) has no macOS Local Network permission: every `adb connect 192.168.1.101:5555` gave "No route to host" while this app's own port scan reached the phone. v20 adds app/Relay.swift: on that exact error the app (which has the permission) opens a relay 127.0.0.1:<port> → phone:5555 and `adb connect`s the relay; loopback is never blocked and the shared server keeps running for Connection Keeper. `linkName2` shows the route behind the relay (Wi-Fi / Tailscale). Seen: Pixel LIVE over the relay, 1920x864, 14 fps; Tailscale route cut with `adb disconnect` → back on Wi-Fi in 3 s.
- **Rotation**: a press is one request seen through. Button dimmed, further presses ignored until the picture on the Mac has turned (at least 1.5 s, at most 6 s); the toggle reads the real picture, not a remembered wish. The phone is asked with auto-rotate off + set-ignore-orientation-request + `cmd window fixed-to-user-rotation -d 0 enabled` (the missing piece: with it the Nothing held landscape 24 s with portrait-only WhatsApp Business in front) + user_rotation + user-rotation lock; read back every 0.4 s for 5 s, asked again once at 2.5 s; a 20 s guard re-asks if the phone goes back (never needed in the tests). Stress: six presses in 2.5 s = one rotation on the Nothing, then one press back; both phones turn in 0.4–0.55 s.
- **Auto-rotate goes off when a phone connects** (its own value kept in UserDefaults autoRotate.<id>) and comes back, with portrait and apps deciding again, when the app quits or the tab is closed (seen in the log on quit: "phone restored").
- Test hook: `open -g screencopy://rotate` = one press on the active tab.
- Open: a phone unplugged while landscape stays landscape until the app sees it again (nothing can reach it). The relay lives inside the app, so the Wi-Fi route exists only while Screen Copy runs.
